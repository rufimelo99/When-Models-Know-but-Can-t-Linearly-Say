Abstract

Large language models can detect vulnerable code, yet the form of vulnerability encoding in their representations remains unclear. We analyze eight code models spanning 6.7B–15B parameters on C programs using three datasets (DeltaSecommits, SVEN and PreciseBugs), comparing two diagnostic tasks on the same representations: identifying what patterns the code instantiates, and determining whether it is vulnerable. Models encode the first with high fidelity.

Under the studied paired C-code datasets and linear-probing setup, vulnerability information is more accessible as a paired relational signal (whether code A is riskier than code B) than as a globally separable categorical label. This structural difference has implications for classification: the model reliably ranks which code is riskier, but standard classifiers on isolated samples achieve limited accuracy because vulnerable and secure samples form overlapping distributions in representation space.

The idea

Global labels blur. Pairs stay sharp.

Project every snippet onto the learned vulnerability direction. Seen one at a time, vulnerable and secure code overlap heavily. Seen as (secure, vulnerable) pairs, almost every pair moves the same way.

Key findings

Models know what the code does, and which is worse

Three numbers carry the paper.

0.877

Functional identity is easy. Median pairwise CWE-type AUROC on DeltaSecommits (Qwen2.5-7B). Mean 91.4% across the 7B models and 90.8% across the 13–15B models.

87–88%

Relative risk is easy. Per-pair alignment from layers 3 to 23, with a cross-model Pearson r of 0.921 and direction cosine ≈ 0.99 across layers.

0.648

Absolute labels are not. Peak AUROC of a global vulnerable-vs-secure probe, about 0.23 below CWE-type separation. A shallow 64-unit MLP probe peaks at 0.635–0.644, so extra nonlinearity doesn't close the gap.

Method

Same representations, two questions

We read residual-stream activations at layers 0–27 and ask two diagnostic questions of the same vectors: what pattern is this? and is it vulnerable?

Pooling. Last-token pooling is near chance for the binary vulnerability probe. Mean-token pooling recovers a modest above-chance signal, so the information is spread across token positions rather than concentrated at the end.

Pairing. For each (secure, vulnerable) pair we compare projections onto a vulnerability direction and report per-pair alignment: how often the vulnerable version projects higher. Evaluation uses cross-validation with bootstrap confidence intervals.

Implications

If vulnerability is encoded mainly as a difference, a single-snippet linear classifier is a limited readout. This suggests comparative settings, such as a change judged against its baseline, may suit these representations better.

Scope. Findings are for paired C-code datasets, linear (and shallow nonlinear) probes, and 6.7–15B models. See the paper's limitations section before generalising.
